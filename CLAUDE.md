# Правила для ИИ-ассистента

API платежей онлайн-школы на FastAPI (тестовое задание Квитто). Описание и принятые решения — в README.md.

## Команды

- Установка: `pip install -r requirements-dev.txt`
- Тесты: `pytest`; через Docker — `docker compose run --rm --build tests` (pytest + ruff)
- Линтер: `ruff check .` и `ruff format --check .`
- Запуск: `uvicorn app.main:app --reload` или `docker compose up --build`

## Правила

- **Деньги — только целые копейки (`int`).** Никаких `float` и `Decimal` в суммах. Проценты и деление —
  целочисленной арифметикой (`//`, `divmod`); если нужно округление, явно указать, в чью пользу.
- **Бизнес-логика — в `app/services/`**, роутеры тонкие: разбирают запрос, вызывают сервис,
  переводят доменные исключения в HTTP-ответы.
- Ошибки валидации — стандартный 422 FastAPI, свой формат не придумывать.
- Не менять зафиксированное поведение без явного согласования: 422 на неизвестный промокод
  и несуществующий тариф, 409 на любой запрещённый переход (включая повтор статуса),
  возврат существующего платежа по `Idempotency-Key`.
- Любое изменение поведения сопровождается тестом. Тесты проверяют результат
  (суммы, статус в базе, число записей), а не только код ответа.
- У каждого теста, фикстуры и тестового модуля — docstring на русском: первая строка — что
  проверяется (по ней ищут тесты), дальше — почему ожидается именно такое поведение, если
  это неочевидно или это наше решение.
- Перед тем как сказать «готово» — прогнать `ruff check .`, `ruff format --check .` и `pytest`.
- Комментарии, docstring'и и README — на русском. Комментарий объясняет «почему», а не «что».
- Код совместим с Python 3.11.
- Не коммитить и не пушить: предложить готовые команды git, коммиты делает человек.
- Без лишних слоёв и абстракций: проект маленький, код должен легко объясняться вслух.
